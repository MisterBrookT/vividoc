Decision Tree Classification

At its core, a decision tree builds a classification model by performing recursive partitioning. This process involves taking the entire dataset and systematically breaking it down into smaller, more homogeneous subsets. Imagine your data points scattered across a two-dimensional grid where the axes represent your features, such as Income and Age. The algorithm’s goal is to draw lines that separate these points into distinct groups based on their class labels.

Geometrically, each "split" in a decision tree corresponds to an axis-aligned decision boundary. If the algorithm decides to split based on feature $x_i$ at a threshold value $t$, it creates a horizontal or vertical line defined by the equation $x_i = t$. This line divides the feature space into two regions:

  • $R_1 = \{X | x_i \le t\}$
  • $R_2 = \{X | x_i > t\}$

The term "recursive" refers to the fact that once the first split is made, the algorithm looks at the resulting subsets and repeats the process. It searches for the next best feature and threshold to further refine the boundaries. This continues until a stopping criterion is met, such as reaching a maximum tree depth or achieving a pure node—a subset where every data point belongs to the same class.

As these splits accumulate, the feature space is carved into a series of hyper-rectangles. In each of these rectangular regions, the model makes a prediction based on the majority class present. The power of this approach lies in its simplicity: even complex, non-linear relationships between variables can be approximated by a series of simple, nested "if-then" rules that define these geometric boundaries.

If the goal of recursive partitioning is to create "pure" subsets, we need a mathematical thermometer to measure the "fever" of impurity within a dataset. In information theory, this thermometer is called Entropy. Entropy quantifies the level of disorder or uncertainty in a given set of data points. If a node contains an equal mix of disparate classes, it is in a state of maximum disorder (high entropy); if every point in a node belongs to the same class, the node is perfectly ordered (zero entropy).

For a binary classification problem with classes $C_1$ and $C_2$, the Entropy $H(S)$ of a set $S$ is calculated using the proportion of items belonging to each class, denoted as $p_1$ and $p_2$. The formula is defined as:

$H(S) = -p_1 \log_2(p_1) - p_2 \log_2(p_2)$

When the distribution is a perfect $50/50$ split, the entropy reaches its peak at $1.0$. Conversely, as one class begins to dominate the set, the entropy drops. This mathematical property allows the decision tree algorithm to evaluate the "quality" of a potential split. We look for the split that results in the greatest reduction in entropy, a metric known as Information Gain.

Information Gain $(IG)$ measures how much "information" we learned about the class labels by partitioning the data based on a specific feature $A$. It is calculated by taking the entropy of the parent node and subtracting the weighted average of the entropy of the child nodes:

$IG(S, A) = H(S) - \sum_{v \in Values(A)} \frac{|S_v|}{|S|} H(S_v)$

The algorithm's strategy is simple yet powerful: at every node, it scans every available feature and every possible threshold, calculates the resulting Information Gain, and selects the path that maximizes this value. By repeatedly choosing the splits that provide the most significant drop in disorder, the tree effectively "squeezes" the uncertainty out of the data until it arrives at a clear, logical classification path.

The structural transformation from a single dataset into a classification model is represented by a hierarchical tree. This architecture begins at the root node, which contains the entire training set. Each subsequent split creates child nodes, further partitioning the data until the process terminates at a leaf node. In these final leaves, no further splits occur, and a class label is assigned based on the plurality of the remaining data points. The complexity of this structure is primarily measured by its tree depth—the length of the longest path from the root to any leaf.

The depth of a tree acts as a double-edged sword in machine learning. A shallow tree, perhaps with a depth of only $1$ or $2$, is easy to interpret but may suffer from underfitting. Because it only makes a few broad generalizations, it might fail to capture the nuanced, non-linear relationships within the features, essentially "oversimplifying" the reality of the data. As we increase the depth $D$, the model gains the capacity to create more $2^D$ potential regions in the feature space, allowing it to wrap around complex data clusters with high precision.

However, an unrestricted tree depth leads to the primary pitfall of decision tree classification: overfitting. If a tree is allowed to grow until every leaf is perfectly pure, it often begins to "memorize" the stochastic noise—random fluctuations or outliers peculiar to that specific training set—rather than identifying generalizable patterns. Such a model will show near-perfect accuracy on its training data but will fail significantly when presented with unseen data.

To balance this trade-off between bias and variance, practitioners often employ hyperparameter tuning. By setting a max_depth or a min_samples_leaf, we can prune the growth of the tree. Mathematically, we seek an optimal complexity where the error on the validation set is minimized, ensuring that our "if-then" logic remains robust enough to handle the inherent uncertainty of real-world predictions.
