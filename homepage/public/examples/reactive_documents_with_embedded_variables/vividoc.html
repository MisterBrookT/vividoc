Reactive documents with embedded variables

In a traditional document, once a word or number is typed onto the page, it remains static. If you decide to change a specific data point—such as a budget figure or a project deadline—you must manually search for every instance of that value and update it one by one. This process is not only tedious but prone to human error, often leading to inconsistent information where one part of the document contradicts another.

Reactive documents solve this by introducing the concept of variables. A variable is a named placeholder that stores a specific value, such as $x = 100$ or $total\_cost = 500$. Instead of typing a literal number into your text, you embed a reference to that variable. When the underlying value of the variable is modified, the change "reacts" through the document, automatically refreshing every linked sentence, table, and formula.

This creates a living document where the relationship between data points is preserved. For example, if you define a variable for a radius $r$, you can link it to a formula for area: $A = \pi r^2$. If you update $r$ from $5$ to $10$, the text describing the area will update instantaneously without any manual recalculation. By decoupling the content from the data, reactive documents ensure that your narrative remains synchronized with your figures at all times.

While variables allow documents to update, the real power of reactivity is unlocked through input controls. In a static document, the reader is a passive consumer of information; in a reactive document, the reader becomes a participant. By integrating UI elements like sliders, toggles, and text fields directly into the prose, we create a bidirectional binding between the reader’s input and the document's logic. This means that when a user moves a slider, the underlying variable updates, which in turn triggers a recalculation of every dependent value in the narrative.

Consider a financial projection where you want to estimate the future value of an investment. Instead of reading a static table, you might use a slider to adjust the interest rate $r$. Through bidirectional binding, the formula for compound interest, $A = P(1 + r)^n$, is re-evaluated in real-time. The UI stays in sync with the data model: the slider position represents the current state of $r$, and the state of $r$ determines the text you see on the screen.

This approach transforms abstract equations into tangible experiences. By manipulating a quantitative value within a narrative context, users can immediately observe the sensitivity of a system. Whether you are adjusting the "shipping cost" variable in a business proposal or the "gravitational constant" $g$ in a physics simulation, bidirectional binding ensures that the interface and the underlying data remain a single, cohesive source of truth.

The true depth of a reactive document is realized through computed properties—variables that do not hold a static value, but instead derive their state from other "upstream" variables. While independent variables serve as the document's primary inputs, computed properties act as the logic layer that connects these inputs into a meaningful network. This creates a dependency graph: a map of relationships where changing a single root value initiates a "chain reaction" or propagation, instantly recalculating every downstream consequence across the entire narrative.

Consider a project proposal that defines two independent variables: the hourly rate $r$ and the number of hours $h$. In a static document, you would manually calculate the total and type it out. In a reactive document, you define a derived variable for the total cost $C$, expressed as the function $C = r \times h$. If the reader adjusts the slider for hours, the document doesn't just update that specific number; it triggers the derived variable to re-evaluate the product, which might then feed into a tax calculation $T = C \times 0.15$, and finally a grand total $G = C + T$.

This automated consistency ensures that the document remains logically infallible. Because these calculations are baked into the document's structure, it is impossible for a reader to see a "total" that contradicts the "unit price." By shifting the burden of calculation from the author to the document itself, we eliminate the risk of mathematical drift. Whether you are modeling a biological population growth $P = P_0 e^{rt}$ or a simple retail discount, derived dependencies guarantee that every word and figure in your narrative reflects a single, unified version of the data.

A reactive document’s most profound capability is its ability to provide multimodal representations of the same data. While text and formulas excel at conveying precision and logic, data visualization offers an intuitive, spatial understanding of magnitude and scale. By binding a single variable to both a numeric value in a sentence and a graphical element—such as a bar height, a point on a coordinate plane, or the radius of a circle—the document addresses multiple cognitive pathways simultaneously. This ensures that the reader does not just see a number change, but feels the impact of that change through immediate visual feedback.

Consider the relationship between a monthly savings rate $s$ and a goal progress bar. In a static report, you might read that "the user has saved $s = \$400$, reaching $80\%$ of their goal." In a reactive context, as you adjust a slider to increase the savings rate, the sentence updates its percentage in real-time, while a progress bar physically expands to fill the screen. This linked reactivity eliminates the cognitive load of mentally translating abstract digits into physical proportions. Whether you are scaling a 3D model by adjusting a length variable $L$ or watching a bell curve shift by modifying the standard deviation $\sigma$, the visual and textual elements remain in perfect mathematical lockstep.

This synchronization transforms data from a list of isolated facts into a dynamic system. When a change in an input variable triggers a concurrent update across a paragraph, a table, and a chart, the document reveals the underlying "shape" of the information. By bridging the gap between symbolic logic and visual perception, reactive documents turn passive charts into exploratory interfaces, allowing users to uncover patterns and outliers that would remain hidden in a series of static snapshots.
