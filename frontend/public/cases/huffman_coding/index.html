Data Compression · Huffman 1952

Huffman Coding

A greedy algorithm that assigns shorter bit strings to more frequent symbols, achieving provably optimal prefix-free compression. The foundation of ZIP, PNG, JPEG, and MP3.

01 — Building the Optimal Tree

Greedy Merging, Optimal Result

In 1952, MIT doctoral student David Huffman was offered a choice by his professor Robert Fano: take a final exam, or find the optimal prefix-free code. Working late one night, Huffman realized that the key was to work bottom-up rather than top-down. His algorithm is elegantly simple: repeatedly merge the two least-frequent symbols into a single "super-symbol," building a binary tree from the leaves up.
The prefix-free property is critical. In a prefix-free code, no codeword is a prefix of any other. This means encoded symbols can be decoded unambiguously without separators — just follow the tree from root to leaf. The Kraft inequality guarantees that a prefix-free code exists for any set of lengths \(\{l_i\}\) satisfying \(\sum_i 2^{-l_i} \leq 1\). Huffman codes achieve equality.
The algorithm's optimality can be proven by induction. At each step, the two least-probable symbols will have the longest codes in any optimal encoding, and they can always be given codes that differ only in the last bit (sibling leaves). Merging them into a combined node with probability \(p_i + p_j\) and solving the sub-problem recursively produces an optimal code for the original problem.

Prefix-free decoding: Because no codeword is a prefix of another, a Huffman-encoded bitstream can be decoded left-to-right by traversing the tree. At each bit, go left (0) or right (1). When you reach a leaf, emit the symbol and return to the root. No lookahead or separators needed — this property is what makes Huffman codes practical for streaming data.
02 — Average Code Length vs Entropy Bound

How Close Can We Get to Entropy?

Shannon's source coding theorem tells us the entropy \(H\) is the theoretical minimum average code length. Huffman coding, despite its simplicity, comes remarkably close. For any source with entropy \(H\), the average Huffman code length \(\bar{L}\) satisfies: \(H \leq \bar{L} < H + 1\). At most one extra bit is wasted per symbol — no other prefix-free code can do better.
The gap \(\bar{L} - H\) arises because Huffman must assign integer-length codewords, but the optimal (non-integer) lengths are \(-\log_2 p_i\) bits. For a symbol with \(p_i = 0.4\), the ideal length is \(-\log_2(0.4) \approx 1.32\) bits — but we must round to 1 or 2. Arithmetic coding sidesteps this by encoding entire sequences at once, asymptotically achieving \(H\) with increasing block length.
The comparison to fixed-length encoding is striking. For 5 symbols, we need \(\lceil \log_2 5 \rceil = 3\) bits per symbol regardless of frequency. If one symbol appears 90% of the time, fixed encoding wastes nearly all its capacity. Huffman adapts: give that symbol a 1-bit code and distribute the savings across rare symbols that appear infrequently anyway.
In practice, DEFLATE (used in ZIP, PNG, zlib) combines Huffman coding with LZ77, a dictionary-based compressor that replaces repeated byte sequences with back-references. The result far exceeds letter-level Huffman because it exploits long-range redundancy. But at the core, Huffman codes are still there — compressing the LZ77 tokens.

Why we can't beat entropy: Any lossless scheme must map distinct messages to distinct bitstrings. There are \(2^k\) bitstrings of length \(k\), so on average you need at least \(\log_2 N\) bits to represent \(N\) equally likely messages. For non-uniform distributions, the entropy is the weighted average of the optimal lengths. Compression below entropy would require two different messages to share the same codeword — making decoding impossible.
03 — English Letter Frequencies

Real-World Compression

English text is far from uniform. The letter 'e' appears in about 12.7% of typed text; 'z' and 'q' appear in fewer than 0.1% each. A Huffman tree built on these frequencies gives 'e' a short code (2–3 bits) while 'z' and 'q' earn long codes (8–10 bits). Since short codes are used most often, the average drops well below 8 bits — the ASCII fixed-length encoding.
Applying Huffman to English letter frequencies yields an average code length of about 4.12 bits, compared to ASCII's 8 bits — roughly a 48% reduction. But this only scratches the surface of English's redundancy. Shannon estimated the true entropy of English (accounting for word-level statistics and grammar) at 1–1.5 bits per character. Modern compressors achieve near this bound by operating on blocks and using context models.
The Lempel-Ziv family of algorithms (LZ77, LZ78, LZW — used in ZIP, gzip, GIF) replaces repeated substrings with pointers to previous occurrences, effectively capturing multi-character statistics. The combination of LZ-style back-references with Huffman coding of the symbols produces DEFLATE — used in gzip, zlib, PNG, and WebP. BZIP2 uses Burrows-Wheeler transform plus Huffman, squeezing even further.
Adaptive Huffman coding dynamically updates the tree as symbols are observed, eliminating the need to transmit the code table as side information. This is used in real-time compression scenarios. More powerful adaptive schemes (PPM, CM) model conditional probabilities and approach Shannon's true entropy of English.

Real-world compression benchmarks: Plain text with gzip: ~60–70% size reduction. PNG images (lossless): 20–50% smaller than BMP depending on content. JPEG uses Huffman to compress DCT coefficients after lossy quantization. H.264/H.265 video use CABAC (context-adaptive binary arithmetic coding) for the residual after motion prediction. In all cases, Huffman's 1952 insight remains at the core.
