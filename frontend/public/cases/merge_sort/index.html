Merge Sort

01 — The Algorithm

Divide, Conquer, Merge

Merge sort splits the array in half recursively until each sub-array has one element (trivially sorted), then merges pairs back in sorted order. The insight: merging two sorted arrays takes O(n) time, and we do O(log n) levels of merging.
Recurrence: \(T(n) = 2T\!\left(\dfrac{n}{2}\right) + \Theta(n)\)  ⟹  \(T(n) = \Theta(n \log n)\)  (Master Theorem, Case 2)

02 — Recursion Tree

The Log n Levels

Every level of the recursion tree does exactly n total work for merging. Since the tree has ⌈log₂ n⌉ + 1 levels, the total is Θ(n log n). The tree below highlights which node is active at each step.
Level 0: 1 merge of n elements  =  n work
Level 1: 2 merges of n/2 elements  =  n work
Level k: \(2^k\) merges of \(n/2^k\) elements  =  n work
Total: \(\log_2 n\) levels × n work  =  \(\Theta(n \log n)\)
03 — Why n log n?

The Information-Theoretic Lower Bound

Any comparison-based sorting algorithm must distinguish between all n! possible orderings of the input. Each comparison provides at most 1 bit of information, so we need at least ⌈log₂(n!)⌉ comparisons.
By Stirling's approximation: \(\log_2(n!) = \Theta(n \log n)\)
Therefore, no comparison sort can beat Θ(n log n) in the worst case. Merge sort achieves this bound.

Merge sort's stability makes it the algorithm of choice when the relative order of equal elements must be preserved — critical for multi-key sorts (sort by last name, then by first name). Java's Arrays.sort for objects and Python's sorted()/list.sort() (Timsort) are both based on merge sort.
